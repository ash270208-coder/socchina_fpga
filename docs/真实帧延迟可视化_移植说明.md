## 2. 原方案与新方案

### 2.1 移植前的做法（本工程原有）

`delay_osd.v` 自己在 HDMI 像素域用 `CLK_FREQ_HZ=75000000` 分频出 1 ms 节拍，测出采集帧周期
`frame_ms`，再按参数 `LAG_SHIFT=1` 显示：

```text
第一行 DELAY:2帧     ← 固定值 LAG_FRAMES=2
第二行 DELAY:066ms   ← 实测帧周期 × 2
```

它回答的是“按帧周期推算，大概两帧”，**不能回答当前屏幕上这一帧到底是哪一帧**，输入暂停、
丢帧或页面复用时数值也不可靠。

### 2.2 移植后的做法（帧标签法）

为每个 CSI 帧首建立 32 位时间戳和帧序号，并在该帧写入 DDR 时把标签绑定到**实际写入页**；
显示帧首发生时用 `video_out` 给出的**实际读取页**取标签，再算差值：

```text
CSI 帧首（CSI 时钟域，csi_unpacket 的 O_csi_frame_start 单拍脉冲）
    │  取上升沿 → toggle
    ▼
DDR 时钟域（66.667 MHz）
    │  32 位 ms_counter（按 DDR_CLK_HZ 分频）+ 32 位 frame_seq（自然回绕）
    │
    ├─ video_in 写帧首 + 实际写页（S_video_in_wp）
    │       └─ 页元数据：page_valid / page_capture_ms / page_frame_seq
    │
    └─ video_out 显示帧首 + 实际读页（I_video_out_rp）
            └─ delay_frames = frame_seq − page_frame_seq
               delay_ms     = ms_counter − page_capture_ms
                    │  请求/应答 toggle 握手
                    ▼
              HDMI 像素域 delay_osd 显示
```

关键点：`video_out` 在 `S_video_frame_start` 那一拍正是用 `I_video_out_rp` 锁存本帧读基地址
（`video_out.v` 的 `O_ddr_user_addr` 分支），跟踪器在同一 DDR 时钟沿采同一个 `rp`，因此
“标签页 == 本帧真正读取的页”，不存在差一页的问题；`video_in` 侧同理，帧首那拍 `S_video_in_wp`
仍是本帧写入页（`wp` 与地址锁存在同一沿更新）。

### 2.3 计算与饱和

```text
delay_frames = frame_seq_now  − page_frame_seq[display_page]   // 32 位模减
delay_ms     = ms_counter_now − page_capture_ms[display_page]  // 32 位模减
```

- 32 位无符号减法在计数器回绕时仍保持正确的模运算语义；
- 输出饱和：帧龄最大 9，毫秒最大 999；
- 页标签无效（首帧未就绪）、同一页读写冲突、CSI 帧首与 DDR 写帧首配对失败 → `delay_valid=0`，
  数字区域不显示，**宁可不显示也不显示错值**；
- 毫秒分频：`DDR_CLK_HZ = 66_666_667`，`MS_DIVISOR = DDR_CLK_HZ / 1000`。
  本工程 `u_ph1p35_324_ddr_wrapper/u_ddr2/usr_clk` 约束周期 15.000 ns = 66.667 MHz
  （`final_timing.rpt` Clock Summary 的 `clk1`），与参数一致；DDR 时钟配置若改，这里要同步改。

## 6. 已知限制

- `DDR_CLK_HZ` 是毫秒准确性的唯一依据，必须与实际 DDR 用户时钟一致（本工程 66.667 MHz）；
- 计时起点是 CSI 解包帧首，不是传感器曝光起点；终点是 DDR 域显示帧首，不等于某个像素到达屏幕；
- 只为 4 个物理页保存元数据，页复用会覆盖旧标签；
- CSI 帧首与 ISP/DDR 写帧首默认一一对应，配对异常时页面置无效、OSD 数字隐藏；
- OSD 只显示 0~9 帧、0~999 ms，超范围饱和；
- B 板工程、网络包格式与 CNN 推理路径未改动。
