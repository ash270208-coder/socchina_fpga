# 直方图均衡（HE）优化记录 · A + E + G

> 实施时间：2026-09-25
> 改动文件：`histogram_equ.v`、`vpp_top.v`
> 仿真环境：`sim/he_ram_stub.v`（TD RAM IP 的行为级桩件）、`sim/histogram_equ_clip_tb.v`、`sim/vpp_top_aln_tb.v`

---

## 1. 问题（用户反馈）

直方图均衡档在**明暗反差大的地方（墙角）**和**大面积单色（白墙）**上噪点很多。

## 2. 根因

| # | 原因 | 说明 |
|---|---|---|
| 1 | **全局 HE 无对比度限制** | 局部增益 = `255·h[i]/N`。白墙这类"某个亮度占画面多数"的场景，增益被放大到 **60~70 倍**，传感器 ±1 LSB 噪声变成 ±69 级 → 满屏颗粒 |
| 2 | **无帧间平滑** | 用上一帧 CDF 且帧帧重算 → 平坦区逐帧呼吸/闪烁（也被感知成噪点） |
| 3 | **模式 2 不过 gamma、不过色度降噪** | 别的档都过 `gamma_lut`（扣黑电平+γ2.2）与 `chroma_nr`，只有它不过 → 色调域不一致 + 彩色噪点直接可见 |
| 4 | **HE 作用在未扣黑电平的线性 Y 上** | 黑电平/暗部噪声一起被拉伸（本次由 E 顺带缓解） |

## 3. 本次改动

### A. 直方图裁剪 + 重分配（`histogram_equ.v`）
- 新增参数 `CLIP_DIV`（默认 **64**）：每个 bin 计数上限 `CLIP = TOTAL_PIXELS / CLIP_DIV`
- 由于增益 = `255·h[i]/N`，限住 h 就等于**限住最大增益**：
  `最大增益 = 255 / CLIP_DIV`（64 → 约 4 倍；32 → 约 8 倍；128 → 约 2 倍）
- 写入 RAM 前饱和；超限像素计入 `excess`（统计阶段顺手累加，**不占额外周期**）
- 消隐期重分配：每个 bin 加 `excess/256`，余数分给前 `excess[7:0]` 个 bin
  → `Σ(CDF 增量)` 严格 = N，**白点不被拉低**；空 bin 被抬起 → **暗部不再被压死**
- ⚠ 踩过的坑：累加器 `his_sum` 必须一起加 `clip_add`，否则"重分配斜坡"不累积，
  白点会从 255 掉到 ~32（仿真抓到并已修）

### E. 模式 2 统一色调域（`vpp_top.v`）
- 模式 2 输出前补一个 `gamma_lut`（**纯组合、0 拍**，不破坏对齐）
- 顺带获得黑电平扣除（原模式 2 完全没扣）

### G. 模式 2 补色度降噪（`vpp_top.v`）
- 模式 2 输出前补 `chroma_nr`（内部 **3 拍**）
- 延迟重新配平：`9 拍(转换) + 0(gamma) + 3(chroma_nr) + 4(he_rgb_d) = 16 拍`（原来 `9 + 7 = 16`）

## 4. 仿真验证结果（ModelSim）

### A：`sim/histogram_equ_clip_tb.v`（64×64，白墙+墙角场景）

| 指标 | 不裁剪 (CLIP_DIV=1) | 裁剪+重分配 (CLIP_DIV=64) |
|---|---|---|
| 白墙处噪声增益 | **69 倍/LSB** | **4 倍/LSB** ✅ |
| 白点 out[255] | 255 | **255** ✅（重分配生效） |
| 暗部 out[0..3] | 0,0,0,0（压死） | **1,2,3,4**（抬起）✅ |
| 直方图计数 | 1110 / 1111 / 1109（正确） | 64/64/64（裁剪生效）✅ |

### E+G：`sim/vpp_top_aln_tb.v`（两种模式同激励，左暗右亮台阶）

| beat | 模式 0（原图+伽马） | 模式 2（HE+gamma+chroma_nr） |
|---|---|---|
| 0~30 | 78（暗） | 82（暗） |
| **31** | **217（跳变）** | **214（跳变）** |
| 32~62 | 217 | 214 |

台阶位置完全相同 → **模式 2 仍然严格落在第 16 拍，画面不会横移** ✅
（暗部 78 vs 82 也说明两者已在同一色调域）
